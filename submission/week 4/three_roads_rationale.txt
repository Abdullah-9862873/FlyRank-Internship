Three Roads: Choose Your Stack with AI

My Four Constraints

1. Free only. No paid hosting, domains, or services.
2. Skill level. Beginner in Python and data analysis. No web development experience. I can follow instructions but cannot debug complex frontend code.
3. Portfolio needs. Based on my sitemap and content map, the portfolio must display: image galleries (screenshots of notebooks, dashboards, charts), embedded code demos (Jupyter notebooks), and long-form writing (research-style writeups of my ML work).
4. Display requirements. Image galleries are essential (6+ screenshots of my work). Long-form reading matters more than interactivity. I do not need user accounts, databases, or dynamic content yet.

Three Stack Options

Option 1: Static HTML/CSS + GitHub Pages (Simplest)

How I would build it. Hand-written HTML pages, one per section. Images stored in an images/ folder. CSS for styling. No build tools, no frameworks.

Where I would host it. GitHub Pages (free, already connected to my repo).

Does it need a backend? No.

Trade-off. Simplest to set up and maintain. I already pushed an index.html to GitHub Pages. But every page must be written manually in HTML. Adding new content means editing raw code. The site will look basic unless I spend time on CSS. No templating means repetitive work if I have many pages.

Option 2: GitHub Pages + Static Site Generator like Jekyll or Hugo (Middle Ground)

How I would build it. Write content in Markdown files. A static site generator converts them to HTML. Templates handle layout and navigation automatically.

Where I would host it. GitHub Pages (free, has native Jekyll support). Netlify or Cloudflare Pages also work (free tiers).

Does it need a backend? No.

Trade-off. I write content once in Markdown and the generator handles the rest. Navigation, image galleries, and styling come from themes. The learning curve is moderate (Markdown syntax, config files). I do not need to touch HTML directly. The risk is spending time on setup instead of content. But once set up, adding new portfolio pieces is just dropping in a Markdown file.

Option 3: Next.js on Vercel (Most Powerful)

How I would build it. React components, JavaScript, TypeScript. Build with next build, deploy automatically.

Where I would host it. Vercel free tier (generous for personal sites).

Does it need a backend? Not yet, but Next.js is built for dynamic features. I could add a backend later without switching stacks.

Trade-off. Most powerful and future-proof. Interactive galleries, smooth navigation, and room to grow. But I have zero React or JavaScript experience. I would be learning two things at once (web framework + deployment). Debugging would be slow. The portfolio would look polished only if I invest significant time learning the framework. Maintenance is ongoing (dependency updates, breaking changes).

Pressure-Test: GitHub Pages (My Front-Runner)

What breaks if I pick the simplest option?
- I cannot easily add interactive elements (search, filtering, animations) without writing JavaScript from scratch.
- The site will look basic. No responsive templates out of the box.
- If my portfolio grows to 20+ pages, maintaining raw HTML becomes tedious.

What do I maintain if I pick the most powerful option?
- React dependencies (npm packages, version conflicts).
- JavaScript build pipeline.
- Debugging browser issues I do not understand.
- Time I could spend on actual portfolio content goes to framework problems.

Can I finish in two weeks?
- GitHub Pages: Yes. I already have index.html live. I can add 4-5 more pages in a weekend.
- Jekyll/Hugo: Maybe. One day to learn, one day to build.
- Next.js: Unlikely without significant time investment.

Does it show my work the way it needs to be shown?
- GitHub Pages handles image galleries (just img tags in HTML). Long-form reading works fine (HTML p tags, readable typography). Embedded notebook screenshots work. I do not need dynamic features yet.

My Decision

I chose GitHub Pages with static HTML/CSS.

Why this stack. I already have a live URL from the previous assignment. The site is free, I control the code, and I can deploy with a single git push. I can finish it in two weeks. My portfolio needs image galleries and long-form writing, both of which work in plain HTML. I do not need a backend or dynamic features yet.

Why not Jekyll/Hugo. The learning curve is real for someone with no web experience. I would spend more time figuring out configuration files than writing content. I can always migrate later if the site grows.

Why not Next.js. I do not know React or JavaScript. Learning a framework while building a portfolio is double the work. The power of Next.js is wasted on a site that needs galleries and text. I can adopt it later if my portfolio demands interactivity.

Can I maintain this? Yes. HTML is plain text. I can edit any page in any editor. There are no dependencies to update, no build steps to break, no version conflicts. The site works as long as GitHub Pages exists.

Does it show my work well? Yes. My work is screenshots of notebooks, charts, and dashboards. An image gallery in HTML displays them clearly. Long-form writeups render well in a browser. The site is readable on any device.
